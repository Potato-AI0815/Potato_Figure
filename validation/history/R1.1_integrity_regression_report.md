# R1.1 Integrity Regression Patch

## Scope

This is a narrow execution-layer patch after the R1 review. The frozen v0.2 architecture was not changed, and no real-data benchmark, new demo, visual-profile expansion, or release operation was performed.

## Blocker 1 — Visual status is derived, not trusted

`scripts/evaluate_readiness.R` now reads all ten required post-render `visual_qa.tsv` domains and derives:

```text
any FAIL        → FAIL
else any REVISE → REVISE
else any NOT_REVIEWED → NOT_REVIEWED
else all PASS   → PASS
```

The contract value is retained as `visual_contract_status`. A mismatch with `visual_derived_status` is reported as `visual_contract_consistency: WARNING`, and cannot produce `PUBLICATION_READY: TRUE`.

## Blocker 2 — Explicit pairing/test contradictions

Scientific Audit now adds `pairing_test_consistency`. It fails only high-confidence contradictions:

- `paired` with rank-sum, Mann–Whitney, Welch, independent, or unpaired terminology;
- `unpaired` with signed-rank or paired-test terminology.

Matching is token-aware: `unpaired` is not treated as a match for the bare `paired` substring. Therefore `unpaired t-test`, `Welch t-test`, and `paired t-test` pass their valid designs. It does not pretend to adjudicate complex mixed, Cox, GEE, or GLMM models.

## Visual-domain uniqueness

The ten required visual domains must each occur exactly once. Missing domains, duplicated domains, extra domains, or invalid statuses make:

```text
VISUAL_QA_INTERFACE = NOT_READY
PUBLICATION_READY = FALSE
```

Status derivation uses named unique rows only after this structural check; it cannot silently ignore duplicates through `match()`.

## Delivery hardening

`delivery_metadata_coverage` requires exactly one metadata row for each primary output × requested format. Missing or duplicate rows fail Delivery QA.

The R1 CI workflow now also triggers for `schemas/**` and `profiles/**` changes.
